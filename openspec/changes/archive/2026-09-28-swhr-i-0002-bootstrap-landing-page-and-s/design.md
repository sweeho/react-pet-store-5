# Design — Bootstrap, landing page and shared site shell

## Context

This change is generated by the platform for every migration and greenfield initiative (architecture doc 41). The idea canvas, its wireframes and its mockups are the detailed design; this document records the decisions every other capability relies on.

## Decisions

- **One shell.** Every page renders inside the same layout, header, navigation and footer. A capability adds content to the shell; it never draws its own chrome.
- **One navigation.** The global navigation lists every primary area and always links back to the landing page. A capability that adds a primary area adds one entry here rather than a second menu.
- **Shared states.** Empty, error and loading frames are components of the shell, reused by every page.
- **Existing boilerplate wins.** Where the repository already has an application scaffold, extend it rather than scaffold again.
- **Sign-in only if the product has it.** The shell carries a sign-in frame only when the product requirements call for authentication.

## Primary areas

- Localization (`localization`)
- Sign-on and access control (`sign-on`)
- Catalog browsing and search (`catalog-browsing`)
- Customer account and profile (`customer-account`)
- Shopping cart (`shopping-cart`)
- Checkout and order placement (`checkout`)
- Order approval (`order-approval`)
- Supplier inventory (`supplier-inventory`)
- Customer notifications (`customer-notifications`)

### Codebase findings

- **Scaffold.** Vite 8 + React 19 SPA and Nitro 3 server in one repo; pages are file-based under `src/pages/` (`vite-plugin-pages`, `importMode: "sync"`), mounted by `useRoutes(routes)` inside `<Suspense fallback={<p>...</p>}>` in `src/main.tsx`. No layout component exists; each page draws its own chrome.
- **Template leftovers.** `src/pages/index.tsx` is the Vortex marketing hero (its own header, `nav[aria-label=Global]`, headlessui mobile `Dialog`), tested by `src/pages/index.test.tsx` and `e2e/home.spec.ts`. `src/pages/about.tsx` and `src/pages/users/*` are demo pages. `src/pages/NotFound.tsx` (via `[...all].tsx`) and `src/pages/RootErrorBoundary.tsx` are bare, unstyled and not wired to anything. `index.html` title is "Vite + React + TS"; `package.json` name is `react-ts-starter`; `STORE_NAME` is a placeholder.
- **Design tokens.** `src/index.css` carries shadcn neutral OKLCH tokens. The mockups are built on the Preline token names (`--background-1`, `--primary-hover`, `--line-2`, `--muted-foreground-1`, …, primary blue) that `design/tokens.theme.css` defines — but that file is not imported anywhere. Preline has no `--ring`, `--input` or `--accent`, which `src/components/ui/button-variants.ts` uses, so the shadcn names must be aliased onto Preline values. Fonts: `configs/fonts.config.ts` loads Space Grotesk; the mockups use Inter plus Noto Sans JP / SC for the language labels.
- **Tailwind config.** An empty `tailwind.config.ts` exists although the conventions say none may.
- **Tests and CI.** Vitest client (jsdom) + server projects, Playwright on :5178 with `e2e/smoke.spec.ts` (root, `/api/hello`, `/api/users`). `.github/workflows/ci.yml` already triggers on `vortex/**` pushes and PRs and runs doc links, typecheck, lint, unit (JUnit uploaded), build, then E2E.
- **Route names used by later changes.** `swhr-i-0005-sign-on-and-access-control` uses `/signin` and puts the header in `src/components/`.

### Decisions taken at planning

- **Primary-area list is one module.** `src/constants/navigation.ts` exports `PET_CATEGORIES` and `PRIMARY_AREAS`; the landing page, the Global navigation and the footer all render from it. Route contract: `/category/{BIRDS|CATS|DOGS|FISH|REPTILES}`, `/search`, `/cart`, `/checkout`, `/account`, `/signin`, `/admin`, `/supplier`. Category ids are the legacy catalogue ids so catalog-browsing can use them unchanged.
- **Placeholder pages.** Each area route gets a placeholder page until its capability ships, so no landing or navigation link hits not-found. The owning capability replaces the file.
- **Landmarks are the contract.** One `banner`, one `navigation` named "Global", one `main`, one `contentinfo` per page; the footer's link list uses a different navigation name. Tests locate the shell by these roles.
- **Tokens.** Adopt `design/tokens.theme.css` (Preline) as the token source in `src/index.css`, aliasing the shadcn names Button uses. Inter body font, Noto Sans JP / SC for language labels.
- **State frames API.** `EmptyState`, `ErrorState`, `LoadingState` and `AsyncContent<T>` in `src/components/state/`. Pages that fetch use `AsyncContent`; not-found and the render-error boundary reuse `ErrorState`.
- **Language flags** render as labels with no behaviour until localization ships; they are not a primary area with a route.

### Phases

1. **Boilerplate and tokens** (SWHR-T-0004) — branding, Preline tokens, fonts, delete `tailwind.config.ts`, root-route smoke test.
2. **Landing page** (SWHR-T-0005) — `navigation.ts`, placeholder area pages, Pet Store home, template demo pages removed.
3. **Site shell** (SWHR-T-0006) — `SiteLayout`, header, Global navigation, footer, mobile menu panel; mounted in `main.tsx`.
4. **Shared frames** (SWHR-T-0007) — state components, `AsyncContent`, Suspense fallback, not-found and error boundary, placeholders on `EmptyState`.
5. **Test harness** — no new tooling. Each task adds its own unit tests (client project) and Playwright specs in `e2e/`; the test cases in `test-cases.md` (SWHR-C-0002…0011) are distributed across tasks 2–4 and named in their acceptance criteria.
6. **CI** — the existing `.github/workflows/ci.yml` already runs every tier on `vortex/**` pushes and pull requests; no workflow change is planned. Each task keeps it green on its branch.

Tasks run strictly in order (each `depends_on` the previous) because phases 2–4 all edit `src/main.tsx`, the placeholder pages or the landing page.

### Spec discrepancies

- **SD-1 — "Primary areas" includes capabilities with no screen.** `proposal.md` and the Primary areas list above name `localization` and `customer-notifications` as primary areas. PRODUCT.md lists no screen for notifications ("E-mail (not screens)") and localization is the language switcher in the header, not a place to navigate to. Conversely `b2b-document-exchange` and `order-fulfillment` are rightly absent. Planning resolves the navigable areas as: shop by pet (5 categories), search, cart, checkout, account, sign in, administration (order-approval) and supplier inventory; localization is served by the header language labels. The scenario "links to every primary area" is tested against `PRIMARY_AREAS`, not against the nine names.
- **SD-2 — Retry label.** `test-cases.md` (SWHR-C-0010/0011) calls the control a "Retry" button; the canvas and the error-state mockup label it "Try again". Build to the mockup ("Try again"); tests query that name.
- **SD-3 — Global navigation contents.** The Global navigation requirement says it has "an entry for each primary area". The site-shell mockup splits those entries between the header actions (Account, Cart, Sign in, staff links) and the Pets menu. Planning keeps one landmark named "Global" wrapping both, so the requirement holds literally.
- **SD-4 — Empty `tailwind.config.ts`.** The repository ships an empty `tailwind.config.ts` although ARCHITECTURE.md and AGENTS.md forbid one; SWHR-T-0004 deletes it.
- **SD-5 — Design guide vs token file.** `design/DESIGN-GUIDE.md` (Meridian) specifies `--ds-*` tokens from `tokens.json` / `tokens.css`, which are not in the repository; the only token file present, and the one the mockups use, is Preline's `design/tokens.theme.css`. Planning adopts the file that exists.
